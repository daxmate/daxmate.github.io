开了终端在跑一个任务，突然想敲别的命令怎么办？关又舍不得关，开新窗口又麻烦。

Shell 提供了前后台任务管理，不用开第二个终端也能解决问题。

---

## 前台 vs 后台

当你敲一个命令，它在终端里运行——这时候叫**前台**。前台任务会霸占终端，你敲不了别的。

如果想让它在背后默默地跑，不挡住你敲其他命令——就叫**后台**。

---

## 启动时直接丢到后台：`&`

在命令末尾加一个 `&`，它就会在后台启动：

```zsh
sleep 30 &
```

```
[1] 12345
```

中括号里的 `[1]` 是**任务编号**，`12345` 是**进程 ID**。

任务在后台跑的时候，终端立刻还给你，你可以继续敲命令。

---

## 把前台任务放到后台：`Ctrl+Z` 和 `bg`

正在前台跑的任务，也可以临时挂起再丢到后台。

```zsh
sleep 300
```

按 `Ctrl+Z`：

```
^Z
[1]  + 12345 suspended  sleep 300
```

任务被挂起了（暂停了），终端还给你。

如果要让它在后台继续跑：

```zsh
bg
```

```
[1]  + 12345 continued  sleep 300
```

`bg` 把最近挂起的任务放到后台继续执行。

---

## 查看后台任务：`jobs`

```zsh
jobs
```

```
[1]  - running    sleep 300
[2]  + running    sleep 100
```

`+` 表示"最近操作过的任务"（默认任务），`-` 表示"上一个默认任务"。

---

## 拉回前台：`fg`

```zsh
fg
```

最近的后台任务拉到前台。

指定某个任务：

```zsh
fg %2       # 把任务 2 拉到前台
fg %sleep   # 按命令名指定
```

---

## 终端关了怎么办：`nohup`

后台任务有一个致命问题：**关掉终端，后台任务也会被杀死**。

```zsh
nohup 长命令 &
```

`nohup`（no hang up）让命令忽略 SIGHUP 信号——终端关闭时不会发给它退出信号。

输出会写到 `nohup.out`：

```zsh
nohup ./long-running-script.sh &
```

```
nohup: ignoring input and appending output to 'nohup.out'
```

可以用重定向指定输出文件：

```zsh
nohup ./long-running-script.sh > mylog.log &
```

---

## 一个完整场景

```zsh
# 1. 启动一个编译任务（后台）
make &

# 2. 查看状态
jobs

# 3. 拉到前台看看进度
fg

# 4. 按 Ctrl+Z 暂停，再用 bg 放回后台
bg

# 5. 做其他事
echo "编译在后台跑，我继续写代码"

# 6. 关终端也不怕——下次用 nohup
nohup make > build.log &
```

---

## 小结

| 操作 | 作用 |
|------|------|
| `命令 &` | 在后台启动 |
| `Ctrl+Z` | 挂起前台任务 |
| `bg` | 挂起的任务在后台继续跑 |
| `fg [%编号]` | 拉到前台 |
| `jobs` | 查看后台任务列表 |
| `nohup 命令 &` | 后台运行，关终端也不停 |

记住 `&` 和 `nohup` 这两个就够了。`bg`/`fg`/`jobs` 偶尔用到，用的时候翻一下这篇文章就行。
