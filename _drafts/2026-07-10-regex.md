前面的文章讲完了通配符和 grep。但很快就碰到一个没法绕过去的问题：

比如要找文件中所有"以 error 开头、后面跟冒号和一个空格、再跟一段数字"的行，通配符完全不够用。

---

### 通配符到正则——第一步

先看一眼两者的区别。之前我们看到的通配符：

```zsh
ls *.txt       # 所有 .txt 结尾的文件
grep foo *.txt  # 在 .txt 文件中搜索 foo
```

这里的 `*` 是 shell 自己的通配符。但当我们用 `grep` 时，传给 grep 的模式是**另一个世界**——正则表达式的世界。

```zsh
grep "foo.*bar" file.txt
```

这里的 `.*` 是正则表达式了，不是 shell 的通配符。`*` 在这个语境下面表示"前面的字符出现零次或多次"，而 `.` 表示"任意一个字符"，合在一起就是"任意内容"。

这个区别是很多人一开始会搞混的地方。记住就行：**引号里面的模式是正则，引号外面的是通配符**（准确说是 shell 的路径扩展）。

---

### 字符集会 —— 用 `[]` 说"我要这几种之一"

和通配符一样，正则也用 `[]` 表示字符集。但语法更丰富一些。

```text
[abc]    → 匹配 a、b 或 c 中的任意一个
[a-z]    → 匹配一个小写字母
[0-9]    → 匹配一个数字
[A-Za-z] → 匹配任意一个字母
```

比如有一个日志文件 `app.log`，内容大概是这样的：

```text
2026-07-10 10:00:23 INFO  Server started on port 8080
2026-07-10 10:01:15 WARN  Disk usage at 85%
2026-07-10 10:02:04 ERROR Disk write failed: no space left
2026-07-10 10:03:11 INFO  Request processed in 234ms
2026-07-10 10:04:55 ERROR Connection timeout to db-primary:5432
```

我们想知道有哪些行是以大写字母开头的——不就是一个 `[A-Z]` 的事情吗？

```zsh
grep '^[A-Z]' app.log
```

但注意，在基础的 grep 中 `^` 表示行首（后面会说到），而 `[A-Z]` 匹配一个大写字母。所以这条命令会返回所有**从 INFO、WARN、ERROR 开头**的行。这里 `^` 的行为和 `[^...]` 不同——前者是锚点，后者是取反。

`[^...]` 的取反就是这个意思：

```text
[^0-9]  → 匹配任意一个非数字字符
[^abc]  → 匹配除了 a、b、c 之外的字符
```

> 这里有一个常见的坑：`^` 放在 `[]` 外面是行首，放在里面才是取反。

---

### 句点 `.` —— 万能牌

`.` 匹配**换行符以外的任意一个字符**。

举个例子：假如我们有几行文本：

```text
cat
cot
cut
c.t
```

用 `grep 'c.t'` 可以匹配到 cat、cot、cut，也会匹配到 c.t——因为 `.` 匹配任何字符，句点本身也不例外。

但想要精确匹配字面量句点，就需要转义：`\.`。

```zsh
grep '\.' app.log    # 找到包含句点的行
```

如果不转义，`.` 会匹配一切。这也是新手最常遇到的问题之一——死活匹配不到句点，结果发现 `.` 是特殊字符。

---

### 用量化符控制次数

为什么说正则比通配符灵活？因为它的量化符——前面的字符出现几次，可以精确控制。

| 量化符 | 含义 | 举例 | 说明 |
|--------|------|------|------|
| `*` | 0 次或多次 | `ab*c` | 匹配 ac、abc、abbc…… |
| `+` | 1 次或多次 | `ab+c` | 匹配 abc、abbc，不匹配 ac |
| `?` | 0 次或 1 次（可选） | `ab?c` | 匹配 ac 或 abc |
| `{n}` | 恰好 n 次 | `a{3}` | 匹配 aaa |
| `{n,}` | 至少 n 次 | `a{2,}` | 匹配 aa、aaa…… |
| `{n,m}` | n 到 m 次 | `a{2,4}` | 匹配 aa、aaa、aaaa |

用刚才的日志文件来试试：

```zsh
grep -E '[0-9]{3,}' app.log
```

这会匹配到包含至少 3 个连续数字的行。上面日志里 `2026`（年份）、`8080`、`234`（来自 234ms）、`5432` 都会命中。而 `85%` 不会被匹配到，因为它只有两位数字。

这里用了 `grep -E`（扩展正则模式），因为 `+`、`?`、`{n,m}` 在基础 grep 中需要反斜线转义（`\+`、`\{n,m\}`）。用 `-E` 就不用转义了，写起来自然很多。

看几个结合起来的例子：

```zsh
# 匹配以 ERROR 开头的行（精确的日志级别）
grep -E '^(INFO|WARN|ERROR) ' app.log

# 匹配包含端口号（如 8080、5432 这种 4 位数字）的行
grep -E '[0-9]{4}' app.log
```

### 锚点：`^` 和 `$`

| 锚点 | 含义 |
|------|------|
| `^` | 行首 |
| `$` | 行尾 |

这两个符号叫"锚点"，因为它们不匹配字符，而是匹配**位置**。

```zsh
# 以 ERROR 开头的行
grep '^ERROR' app.log

# 以数字结尾的行
grep '[0-9]$' app.log

# 空行
grep '^$' app.log
```

`^$` 组合在一起可以精确匹配空行。结合 `.` 和 `*`，写一个匹配"整行任意内容"的正则：`^.*$`。

### 字符集速记符

有些字符集太常用了，所以有专门的缩写。

| 速记符 | 等价写法 | 含义 | 备注 |
|--------|----------|------|------|
| `\d` | `[0-9]` | 一个数字 | grep 基础模式不支持 |
| `\w` | `[A-Za-z0-9_]` | 一个单词字符（字母、数字、下划线） | 同上 |
| `\s` | `[ \t\r\n\f]` | 一个空白字符（空格、制表符等） | 同上 |
| `\D` | `[^0-9]` | 一个非数字 | 同上 |
| `\W` | `[^A-Za-z0-9_]` | 一个非单词字符 | 同上 |
| `\S` | `[^ \t\r\n\f]` | 一个非空白字符 | 同上 |

这些速记符在基础 grep 中是不认的——需要 `grep -P`（GNU grep 才支持）。macOS 默认的 BSD grep 没有 `-P` 选项，但我们可以用 `grep -E` 配合手写字符集，或者直接装个 `brew install grep` 用 `ggrep`。

说到工具差异，这里先整理一张表：

| 命令 | 模式 | 备注 |
|------|------|------|
| `grep` | BRE（基础正则） | `+`、`?`、`()` 需要 `\+`、`\?`、`\(\)` |
| `grep -E` | ERE（扩展正则） | `+`、`?`、`()` 直接写，方便 |
| `grep -P` | PCRE（Perl 兼容） | 支持 `\d`、`\s`、前瞻等，macOS 默认没有 |
| `sed`（默认） | BRE | `\(\)` 分组，`\1` 引用 |
| `sed -E` | ERE | macOS 上可用 `sed -E` |
| Python `re` | 类似 PCRE | 用 `\d`，支持前瞻断言 |

### 分组与捕获：括号的真正威力

括号 `()` 有两个作用：一是改变优先级（像数学表达式那样），二是**捕获匹配到的内容以便后面使用**。

比如这样一个场景——从访问日志中提取 IP 地址：

```text
192.168.1.1 - - [10/Jul/2026:10:15:23 +0800] "GET /api/users HTTP/1.1" 200 1234
10.0.0.5   - - [10/Jul/2026:10:15:24 +0800] "POST /api/login HTTP/1.1" 401 56
192.168.1.1 - - [10/Jul/2026:10:15:25 +0800] "GET /api/users HTTP/1.1" 200 1234
```

用 `sed` 提取出 IP 地址和时间：

```zsh
sed -E 's/^([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+).*\[([^]]+)\].*$/\1  \2/' access.log
```

这里 `(...)` 圈出了两部分内容：IP 地址和时间戳。`\1` 指向第一个括号捕获的内容，`\2` 指向第二个。

在 `sed` 中，搜索和替换都用 `\(`（基础模式）或 `(`（扩展模式 `-E`）捕获，替换部分用 `\1`、`\2` 引用。这个和 grep 的 `-o` 结合 `\1` 的用法不太一样——在 grep 中，我们使用的是**正则表达式的匹配结果**，而非替换。

来看一个用 grep 提取 IP 的例子：

```zsh
grep -oE '([0-9]+\.){3}[0-9]+' access.log | sort | uniq -c | sort -rn
```

这条命令先提取所有 IP，计数排序，就能看到哪个 IP 访问最频繁。

### 贪婪 vs 懒惰

这也是初学者和中级用户都反复踩坑的地方。

默认情况下，`*` 和 `+` 都有点贪心——它们会尽量多地匹配字符。

```text
文本："<div>hello</div><p>world</p>"
正则：<.+>
```

贪婪匹配的结果是：`<div>hello</div><p>world</p>`——从第一个 `<` 吃到了最后一个 `>`。

如果我们需要的是每一个标签单独匹配，就要用**懒惰**模式：

```text
正则：<.+?>
```

这时候会匹配到：`<div>` 和 `</div>` 和 `<p>` 和 `</p>`。`+?` 告诉引擎"匹配最少需要的"。

| 贪婪 | 懒惰 | 含义 |
|------|------|------|
| `*` | `*?` | 尽量多 vs 尽量少，都可以是 0 次 |
| `+` | `+?` | 尽量多 vs 尽量少，至少 1 次 |
| `?` | `??` | 尽量匹配 vs 尽量不匹配 |
| `{n,m}` | `{n,m}?` | n 到 m 次，尽量少 |

```zsh
# 贪婪：取出 TODO 和第一个 DONE 之间的所有内容
echo "TODO: fix the bug and refactor DONE: done" | grep -oE 'TODO.*DONE'
# 输出: TODO: fix the bug and refactor DONE

# 懒惰：取 TODO 和最近的 DONE 之间的最少内容
# grep -P 'TODO.*?DONE' （如果 -P 可用）
# 或者用 Python 来做
```

注意：`grep -E` 其实不支持懒惰模式——因为它还是 ERE，不是 PCRE。懒惰模式 `*?` 是 PCRE 的特性。所以要用懒惰模式，要么 `grep -P`（GNU grep），要么 `pcregrep`，要么直接用 Python 或 JavaScript 处理。

### 前瞻断言

前瞻断言是正则中"只看不拿"的匹配方式。

```perl
(?=...)   # 正向前瞻：后面必须跟着 ...
(?!...)   # 负向前瞻：后面不能跟着 ...
```

举个例子——找到所有 `ERROR` 但只限于后面跟数字代码的：

```text
ERROR 500: Internal Server Error
ERROR 404: Not Found
ERROR: Some random error without code
WARNING 500: Just a warning
```

```zsh
# 如果 -P 可用
grep -P 'ERROR (?=\d+)' app.log
```

这只会匹配前两行中的 `ERROR `，匹配到的结果不包括数字本身——前瞻部分不消耗字符。

同样的需求在 Python 中：

```python
import re
log = open('app.log').read()
matches = re.findall(r'ERROR (?=\d+)', log)
# 匹配到: ['ERROR ', 'ERROR ']
```

Python 中也可以用 `(?<=...)`（正向后顾）和 `(?<!...)`（负向后顾），不过本篇不展开。

### 实战：日志分析

来一个完整的例子。假设我们有这样一个日志文件（`server.log`）：

```text
[2026-07-10 10:00:00] [INFO] [MainThread] Application started
[2026-07-10 10:00:05] [INFO] [DBPool] Connected to pg://db-primary:5432/app
[2026-07-10 10:01:12] [WARN] [DBPool] Connection pool at 85% capacity (85/100)
[2026-07-10 10:02:34] [ERROR] [Worker-3] Failed to process order #ORD-20260710-001: timeout after 30s
[2026-07-10 10:02:35] [ERROR] [Worker-3] Retry attempt 1/3 for order #ORD-20260710-001
[2026-07-10 10:02:40] [ERROR] [Worker-3] All retries exhausted for order #ORD-20260710-001
[2026-07-10 10:02:41] [ERROR] [Dispatcher] Sending alert for order #ORD-20260710-001
[2026-07-10 10:03:00] [INFO] [HealthCheck] Status: OK (uptime 180s)
[2026-07-10 10:04:15] [WARN] [DBPool] Connection pool at 90% capacity (90/100)
```

来做几个操作：

```zsh
# 1. 找出所有 ERROR 行
grep '\[ERROR\]' server.log

# 2. 找出 ERROR 行中涉及 Worker-3 的
grep '\[ERROR\].*Worker-3' server.log

# 3. 统计每种日志级别的数量
grep -oE '\[(INFO|WARN|ERROR)\]' server.log | sort | uniq -c
# 输出:
#    3 [ERROR]
#    2 [WARN]
#    3 [INFO]
```

还可以更复杂一点——把订单编号提取出来：

```zsh
grep -oE '#ORD-[0-9]{8}-[0-9]{3}' server.log | sort -u
# 输出:
# #ORD-20260710-001
```

或者用 sed 把日志转成 CSV：

```zsh
sed -E 's/^\[([^]]+)\] \[([^]]+)\] \[([^]]+)\] (.*)$/\1,\2,\3,"\4"/' server.log
```

把第一行变成：

```text
2026-07-10 10:00:00,INFO,MainThread,"Application started"
```

### 各工具中的正则差异

同一段正则，在不同工具里行为不一样。这大概是正则最让人头疼的地方之一。整理一下主要差异：

**grep 的三种模式：**

1. **基础模式**（`grep` 默认）—— `+` 和 `?` 要写成 `\+`、`\?`，括号要写成 `\(\)`。不推荐手动写，直接用 `-E` 省心。
2. **扩展模式**（`grep -E`）—— `+`、`?`、`()` 不需要转义，和 Perl/Python 一致。推荐日常使用。
3. **Perl 模式**（`grep -P`）—— 支持 `\d`、`\s`、前瞻等全部 PCRE 特性。macOS 默认没有，需装 `brew install grep` 后用 `ggrep -P`。

**sed 的替换模式：**

```zsh
# 基础模式：括号要转义
sed 's/\(foo\)bar/\1baz/' file.txt

# 扩展模式（macOS 用 -E，GNU 也支持 -E）
sed -E 's/(foo)bar/\1baz/' file.txt
```

**Python 中：**

```python
import re

# 搜索
m = re.search(r'(?P<date>\d{4}-\d{2}-\d{2})', text)
if m:
    print(m.group('date'))    # 用名字引用
    print(m.group(1))          # 用数字引用

# 替换
text = re.sub(r'(\d{4})-(\d{2})-(\d{2})', r'\3/\2/\1', text)
```

Python 中常见的坑：`re.match()` 是从字符串开头匹配，`re.search()` 在整个字符串中找第一个匹配，`re.findall()` 找所有匹配。这个和 grep 默认的全行搜索行为不一样——grep 更像 `re.findall()` + 按行输出。

### 一张表回顾所有元字符

| 元字符 | 含义 | 示例 | 命中 | 不命中 |
|--------|------|------|------|--------|
| `.` | 任意字符（除换行） | `c.t` | cat、c.t | ct |
| `^` | 行首锚点 | `^foo` | "foo bar"（行首） | "bar foo" |
| `$` | 行尾锚点 | `bar$` | "foo bar"（行尾） | "bar foo" |
| `*` | 前一个字符 0~∞ 次 | `ab*c` | ac、abc、abbc | abdc |
| `+` | 前一个字符 1~∞ 次 | `ab+c` | abc、abbc | ac |
| `?` | 前一个字符 0~1 次 | `ab?c` | ac、abc | abbc |
| `[]` | 字符集 | `[aeiou]` | a、e、i | b、c |
| `[^]` | 取反字符集 | `[^aeiou]` | b、c | a、e、i |
| `()` | 分组+捕获 | `(foo)` | 捕获"foo" | — |
| `\|` | 或 | `foo\|bar` | foo 或 bar | baz |
| `\d` | 数字 [0-9] | `\d{3}` | 123、456 | abc |
| `\w` | 单词字符 [A-Za-z0-9_] | `\w+` | hello、test_1 | hello world（不含空格） |
| `\s` | 空白字符 | `a\sb` | "a b"（a空格b） | "ab" |
| `*?` | 懒惰匹配（最少） | `a.*?b` | "a b" 最小范围 | 最长范围 |
| `(?=)` | 正向前瞻 | `x(?=y)` | x（后面有y） | x（后面无y） |

---

### 几个小建议

写多了就会发现，真正提升效率的不是背多少元字符，而是几个习惯：

1. **写之前先拆**。别想把一整段需求一次性塞进一个正则。先匹配大块的，再逐步细化。
2. **直接用 `-E`**。少写一堆转义反斜线，读起来也舒服。
3. **去 regex101.com 上试**。输入几行测试数据，看匹配结果，远比猜来猜去快。
4. **多用命名组**。Python 中 `(?P<name>...)` 比 `(...)` 好维护，回头再读代码自己也能看懂。
5. **知道什么时候不用正则**。有时候几个 `grep` 管道串起来，比一个又臭又长的 regex 更清晰。正则好用，但不是锤子。
