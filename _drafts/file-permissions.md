在前面几篇里，`ls -l` 结果的第一列每次都出现——`drwx------`、`-rw-r--r--` 这种东西。聊过一嘴说这是文件权限，但一直没展开。

这篇把这件事说清楚。

---

## 先看看它长什么样

打开终端，随便进个目录，敲：

```zsh
ls -la
```

会看到类似这样的输出：

```
drwx------@  6 dax  staff    192  6月 30 15:00 .
drwx------+  4 dax  staff    128  6月 30 14:30 ..
-rw-r--r--   1 dax  staff     42  6月 30 10:00 hello.txt
drwxr-xr-x   3 dax  staff     96  6月 29 12:00 my-project
-rwxr-xr-x   1 dax  staff    128  6月 28 09:00 script.sh
```

我们关注第一列那串字符（忽略最后的 `@` 和 `+`，那是 macOS 扩展属性标记）。

以 `-rw-r--r--` 为例，把它切成四块：

```
-  rwx  r-x  r-x
│  │    │    │
│  │    │    └── 其他人的权限
│  │    └────── 所属用户组的权限
│  └────────── 所有者的权限
└──────────── 文件类型
```

总结下来就四个问题：

1. **这是文件还是目录？**（第 1 位）
2. **所有者能干什么？**（第 2-4 位）
3. **组员能干什么？**（第 5-7 位）
4. **其他人能干什么？**（第 8-10 位）

---

## 第 1 位：文件类型

| 字符 | 含义 | 举例 |
|------|------|------|
| `-` | 普通文件 | `hello.txt` |
| `d` | 目录 | `my-project` |
| `l` | 符号链接 | 快捷方式 |

日常打交道的基本就是这三种。`l` 表示链接——相当于 Windows 的快捷方式，后面会专门聊。

---

## 后面 9 位：权限三组

`r`、`w`、`x` 各代表一个开关：

| 字母 | 全写 | 含义 |
|------|------|------|
| `r` | read | 读取 |
| `w` | write | 写入（修改） |
| `x` | execute | 执行 |
| `-` | — | 这个位置没权限 |

然后这三个开关重复三次——分别给**所有者**、**用户组**、**其他人**。

举个例子，`-rw-r--r--` 拆开来看：

```
-  文件类型：普通文件
rw-  所有者：能读、能写，不能执行
r--  组员：只能读，不能写不能执行
r--  其他人：也只能读
```

翻译成人话：*这是一个普通文件，主人可以随便改，别人只能看。*

再看 `-rwxr-xr-x`：

```
-  普通文件
rwx  所有者：读、写、执行，全开了
r-x  组员：能读、能执行，不能写
r-x  其他人：同上
```

这是一个可执行脚本，主人能编辑能跑，别人只能跑不能改。

---

## 目录权限的含义不太一样

文件和目录的 `r`、`w`、`x` 含义有微妙的区别：

| 权限 | 对文件的意义 | 对目录的意义 |
|------|------------|------------|
| `r` | 可以看文件内容 | 可以列出目录里的文件名（`ls`） |
| `w` | 可以修改文件内容 | 可以在目录里创建/删除文件 |
| `x` | 可以执行这个文件 | 可以进入这个目录（`cd`） |

一个常见的情况：目录有 `r` 但没 `x`——能看到目录里有啥文件名，但进不去。目录有 `x` 但没 `r`——能进去，但 `ls` 看不见东西。

---

## 改权限：`chmod`

`chmod` 是 **Change Mode** 的缩写。

### 符号法

最直观的写法：

```zsh
chmod u+x script.sh    # 给所有者加执行权限
chmod g-w notes.txt    # 去掉组员的写权限
chmod o+r report.txt   # 给其他人加读权限
chmod a+x script.sh    # 给所有人加执行权限
```

字母含义：

| 字母 | 谁 | 字母 | 操作 | 字母 | 权限 |
|------|---|------|------|------|------|
| `u` | 所有者 | `+` | 加上 | `r` | 读 |
| `g` | 组 | `-` | 去掉 | `w` | 写 |
| `o` | 其他人 | `=` | 设为 | `x` | 执行 |
| `a` | 所有人 | | | | |

### 数字法

等你看熟了符号法，会发现有一种更快的写法——八进制数字：

```zsh
chmod 755 script.sh    # rwxr-xr-x
chmod 644 notes.txt    # rw-r--r--
chmod 600 secret.txt   # rw-------
```

怎么算的？`r=4, w=2, x=1`，每组三个数字加起来：

```
rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
r-- = 4+0+0 = 4
```

所以 `755` 就是 `rwxr-xr-x`，`644` 就是 `rw-r--r--`。

数字法多练几次就熟了。日常最常用的三个组合——

| 数字 | 权限 | 用途 |
|------|------|------|
| `755` | `rwxr-xr-x` | 可执行脚本、目录 |
| `644` | `rw-r--r--` | 普通文件，自己能改别人能看 |
| `600` | `rw-------` | 私密文件，只有自己能看能改 |

---

## 递归改目录

如果想把整个目录的权限一起改，加 `-R`（大写）：

```zsh
chmod -R 755 my-project/
```

目录本身和里面的所有文件都会被改。注意 `-R` 是递归——做之前想清楚。

---

## `chown`：改文件的主人

`ls -l` 里的 `dax staff` 分别是所有者和用户组。如果需要把文件转给别人（比如给 root 或给另一个用户），用 `chown`：

```zsh
chown alice hello.txt           # 所有者改成 alice
chown alice:staff hello.txt     # 所有者和组一起改
```

日常基本用不到 `chown`——自己的文件自己管。但安装某些软件、改系统配置的时候会碰上。

## 常见的用户组

`ls -l` 里 `staff` 这个词，其实是一个用户组。每个用户至少属于一个组，文件也归属于某个组。

macOS 上默认的组：

| 组名 | 干什么的 |
|------|---------|
| `staff` | 所有普通用户的默认组，`/Users` 下的文件默认归它 |
| `admin` | 管理员组，组员可以用 `sudo` |
| `wheel` | 和 `admin` 类似，BSD 传统遗留下来的 |
| `everyone` | 顾名思义，所有用户 |

Linux 上常见的：

| 组名 | 干什么的 |
|------|---------|
| `users` | 普通用户组 |
| `sudo` / `wheel` | 有 sudo 权限的用户 |
| `www-data` | Web 服务器用这个组读写网站文件 |
| `docker` | Docker 用户组，加了才能免 sudo 用 Docker |

看自己属于哪些组：

```zsh
groups
```

日常几乎只跟 `staff` 打交道，知道其他组的存在就行。等以后配服务器、装 Docker 的时候，自然会碰到 `www-data` 和 `docker`。

## 动手试试

```zsh
cd ~
mkdir perm-test && cd perm-test

# 创建几个文件
touch public.txt private.txt script.sh

# 看看默认权限
ls -la

# 试试各种 chmod
chmod 644 public.txt
chmod 600 private.txt
chmod 755 script.sh

# 看看效果
ls -la

# 试着给所有人加执行权限
chmod +x script.sh

# 清理
cd ~ && trash perm-test
```

---

## 小结

`ls -l` 里第一列那些看起来吓人的字符，拆开来看就是四件事：

| 位置 | 内容 | 看什么 |
|------|------|--------|
| 第 1 位 | `d` / `-` / `l` | 文件类型 |
| 第 2-4 位 | `rwx` | 所有者权限 |
| 第 5-7 位 | `rwx` | 组员权限 |
| 第 8-10 位 | `rwx` | 其他人权限 |

改权限用 `chmod`，两种写法：符号法 `u+x`（适合初学）、数字法 `755`（熟练后更快）。

日常记住三个数字就够了：`755`（脚本/目录）、`644`（普通文件）、`600`（私密文件）。
