之前我们讲过「终端」和「Shell」不是一回事。但有一个问题没讲：**终端上那些奇怪的行为是怎么来的？**

比如：
- 为什么 Ctrl+H 是退格？
- 为什么 Ctrl+C 能杀掉程序？

这些不是谁拍脑袋设计的。它们是几段历史的共同遗产——从电报机到打字机，到计算机终端，一直传到现在。

---

## 一切从电报开始

1869 年，股票行情机（stock ticker）诞生了。它通过电线把股票价格从纽约传送到其他地方，在纸带上打印出来。

这个想法后来发展成了**电传机（Teletype）**。电传机本质上是一个远程打字机——你在一个键盘上敲字，远处的另一个机器会自动打出来。

最早的电传网络叫 Telex，在全球范围内传输商业电报。那时候还没有电脑这回事——全是纯机械装置，靠穿孔纸带传输信息。

关键转折发生在 1950 年代：**人们开始把电传机接在电脑上**。

那时电脑还是房间那么大，没有显示器，没有键盘。人怎么跟它交互？最简单的方法就是：用电传机打字进去，它打印输出出来。

```
[打字机/键盘] → 电线 → [电脑]
```

这就是「终端」（terminal）这个名字的来源——它是一根线的**末端**，人坐在那一头跟电脑对话。

## ASCII：把文字翻译成数字

电传机和电脑之间传输的都是二进制数据。需要一套标准来规定：**哪个数字代表哪个字母**。

1962 年，ASCII（American Standard Code for Information Interchange）标准诞生。它用 7 个二进制位表示一个字符，一共 128 个。

这 128 个码点分成两部分：

- **95 个可打印字符**：A-Z、a-z、0-9、标点符号
- **33 个控制字符**：不打印的"指令"

控制字符就是这篇文章的主角。它们都在 ASCII 表的第 1 列——编号 0 到 31。

---

## Ctrl 键的秘密：清掉高位

打开一张 ASCII 表看得更清楚：

![ASCII 表]({{ site.url }}{{ site.baseurl }}/assets/images/ascii-table.svg)

把两样东西放在一起看：

```
十六进制   二进制            字符
0x41  =  0100 0001     'A' (65)
0x61  =  0110 0001     'a' (97)
0x01  =  0000 0001     Ctrl+A (1)
```

看出规律了吗？不管大写 `A` 还是小写 `a`，**清掉高两位（第 6 位和第 7 位）**之后，都落到了同一个控制字符上。

二进制的角度更清楚：

```
'A' = 0100 0001   → 清掉高两位 → 0000 0001 = Ctrl+A
'a' = 0110 0001   → 清掉高两位 → 0000 0001 = Ctrl+A
```

对大小写字母来说，高两位的区别是 `01`（大写区）和 `10`（小写区），Ctrl 键把它们全抹成 `00`，字母就进了第 1 列——控制字符区。

所以 Ctrl+H 不管按的是 `h` 还是 `H` 都能得到退格：

```
'H' = 0100 1000 → 清掉高两位 → 0000 1000 = 8（BS）
'h' = 0110 1000 → 清掉高两位 → 0000 1000 = 8（BS）
```

这也是为什么 Ctrl+字母**只能组合 26 个**（A-Z），因为只有字母对应 `0x41-0x5A`（大写）和 `0x61-0x7A`（小写）这个范围，清掉高位后落在 `0x01` 到 `0x1A`。Ctrl+1、Ctrl+2 没有对应的控制字符——它们跟直接按 1、2 是一回事。

> 所以「减去 64」的说法只在大写字母上成立，准确的说法是**清掉高两位（AND 0x1F）**。

### Ctrl 只是最老的修饰键之一

早期的电传机键盘很简单——除了字母、数字和标点，只有两个修饰键：

- **Shift** — 从打字机继承的，切换大小写和符号
- **Ctrl** — 电传机引入的，修改字符编码来生成控制字符

没有 Alt，没有 Meta，没有 Command，没有 Windows 键。

这些是后来才出现的：

| 修饰键 | 来源 | 年代 |
|--------|------|------|
| Shift | 打字机 | 1800s |
| **Ctrl** | 电传机 | **1960s** |
| **Alt** | **IBM PC** | **1981** |
| Meta | MIT AI Lab | 1970s |
| Command (⌘) | Macintosh | 1984 |
| Windows | Microsoft | 1995 |
| Fn | 笔记本键盘 | 1990s |

因为早期 Unix 机器的键盘上经常没有 Alt 或 Meta 键，人们发明了一个替代方案：**先按 `Esc`、松开、再按字母**，来模拟 Meta+字母。这就是为什么 Emacs 里 `M-x` 在终端里可以用 `Esc` `x` 代替——Vim 和 Emacs 至今还保留着这个用法。

## 各个控制键的前世今生

理论讲完了，来看我们每天按的那些键到底在做什么。

### Ctrl+H = 退格（Backspace）

ASCII 编号 8，名字叫 **BS（Backspace）**。电传机上就是让打印头往回退一格。今天你按 Backspace 键，终端发出去的仍然是 `0x08`（Ctrl+H）。

有些系统上 Backspace 发的是 `0x7F`（DEL，127），这也是历史遗留——看终端配置。

### Ctrl+I = Tab

ASCII 9，**HT（Horizontal Tab）**。电传机上就是让打印头跳到下一个制表位。所以 Ctrl+I 跟 Tab 键是**完全同一个东西**——终端分不清你按的是 Tab 还是 Ctrl+I。

### Ctrl+J = 换行（LF）和 Ctrl+M = 回车（CR）

ASCII 10 和 13。

这两个来自打字机的物理操作：
- **回车（CR）**：把打印头滑到行首
- **换行（LF）**：把纸张往上推一行

在电传机上，换行需要两步。后来 Unix 简化为一个 LF（\n）就够了，但 Windows 还保留着 CR+LF（\r\n）的传统。

### Ctrl+C = 中断（SIGINT）

ASCII 3，**ETX（End of Text）**。最初的意思是"文本结束"。

Unix 把它赋予了新含义：**给前台进程发 SIGINT 信号**。操作系统终端驱动层看到 `0x03` 进来，不是转发给程序，而是直接给它发一个中断信号。

这就是为什么 Ctrl+C 能杀掉大多数程序——它绕过了程序本身，是操作系统在动手。

### Ctrl+D = EOF（End of File）

ASCII 4，**EOT（End of Transmission）**。电报时代的"发完了"。

在终端里，如果在空行按 Ctrl+D，Shell 会认为输入结束了——相当于告诉 Shell "没有更多输入了"。这就是为什么在 `cat` 命令下按 Ctrl+D 会退出，在 Shell 里按会登出。

### Ctrl+Z = 挂起（SIGTSTP）

ASCII 26，**SUB（Substitute）**。

Unix 用它挂起当前程序——相当于按了暂停。用 `fg` 或 `bg` 可以恢复。

### Ctrl+L = 清屏（Form Feed）

ASCII 12，**FF（Form Feed）**。打印机时代的"翻页"。现在终端模拟器把它解释为清屏——跟敲 `clear` 一样。

### Ctrl+[ = Escape

ASCII 27，**ESC（Escape）**。

```
'[' = 91
91 - 64 = 27 → ESC
```

这解释了为什么 Vim 里 `Ctrl+[` 跟 `Esc` 是同一个效果——它们本来就是同一个字符。终端和应用都分不清你按的是 `Esc` 键还是 `Ctrl+[`。

ESC 也是 **转义序列（escape sequences）** 的开头——方向键 `←` 发送的就是 `ESC [ D`，`F1` 发送 `ESC O P`。终端模拟器通过 ESC 后面跟的字符序列来判断你按了哪个特殊键。

### Ctrl+\ = 强制退出（SIGQUIT）

ASCII 28，**FS（File Separator）**。今天被 Unix 重新定义为 SIGQUIT——比 Ctrl+C 更狠的信号。它会强制终止程序并生成 core dump（内存快照）。

```zsh
# 如果 Ctrl+C 杀不掉的程序，试试 Ctrl+\
# 终端会显示：Quit: 3
```

### Ctrl+U / Ctrl+W / Ctrl+A / Ctrl+E

这些不是 ASCII 标准的原始含义——它们是 readline 库定的快捷键。具体列表见下方完整控制字符一览。

## 控制字符一览

ASCII 定义了 33 个控制字符（0–31 + DEL），这里分类列出日常常见的：

### 仍在日常使用的

| 快捷键 | 编号 | 名称 | 今天的作用 |
|--------|------|------|-----------|
| Ctrl+G | 7 | BEL | 响铃/通知 |
| Ctrl+H | 8 | BS | 退格（Backspace） |
| Ctrl+I | 9 | HT | Tab |
| Ctrl+J | 10 | LF | 换行（Unix 行尾） |
| Ctrl+L | 12 | FF | 清屏（翻页） |
| Ctrl+M | 13 | CR | 回车 |
| Ctrl+[ | 27 | ESC | Escape / 转义序列开头 |
| — | 127 | DEL | 删除（有些系统 Backspace 发的是这个） |

### 被 Unix 重新定义的操作系统层控制

| 快捷键 | 编号 | 名称 | Unix 赋予的新含义 |
|--------|------|------|------------------|
| Ctrl+C | 3 | ETX | 中断程序（SIGINT） |
| Ctrl+D | 4 | EOT | 结束输入（EOF） |
| Ctrl+Z | 26 | SUB | 挂起程序（SIGTSTP） |
| Ctrl+\\ | 28 | FS | 强制退出（SIGQUIT） |

### 被 readline / Shell 线编辑复用

| 快捷键 | 编号 | 名称 | Shell 中的用途 |
|--------|------|------|---------------|
| Ctrl+A | 1 | SOH | 跳到行首 |
| Ctrl+B | 2 | STX | 后退一个字符 |
| Ctrl+E | 5 | ENQ | 跳到行尾 |
| Ctrl+F | 6 | ACK | 前进一个字符 |
| Ctrl+K | 11 | VT | 删到行尾 |
| Ctrl+N | 14 | SO | 下一条历史 |
| Ctrl+P | 16 | DLE | 上一条历史 |
| Ctrl+R | 18 | DC2 | 反向搜索历史 |
| Ctrl+T | 20 | DC4 | 交换两个字符 |
| Ctrl+U | 21 | NAK | 删到行首 |
| Ctrl+W | 23 | ETB | 删掉前一个词 |
| Ctrl+X | 24 | CAN | 扩展命令 |
| Ctrl+Y | 25 | EM | 粘贴刚才删的内容 |

### 纯历史遗产，今天基本不用

剩下 6 个来自电报时代，现代终端中几乎没有实际作用：

| 编号 | 名称 | 原文含义 |
|------|------|----------|
| 0 | NUL | 空字符（填充用） |
| 15 | SI | 切换字符集 |
| 22 | SYN | 同步空闲 |
| 29 | GS | 组分隔符 |
| 30 | RS | 记录分隔符 |
| 31 | US | 单元分隔符 |

## 可以用 stty 查看和修改映射

系统和 Shell 怎么处理这些控制字符，可以通过 `stty` 查看：

```zsh
stty -a
```

```
intr = ^C; quit = ^\; erase = ^?; kill = ^U; eof = ^D;
start = ^Q; stop = ^S; susp = ^Z; werase = ^W; ...
```

理论上可以用 `stty` 把 `intr` 改成别的键，但建议别这样干——会把自己搞糊涂。

如果终端状态乱了：

```zsh
stty sane
```

这是一个恢复的"急救"命令。

## 今天的终端

今天我们用的不是真电传机。Terminal.app、iTerm2、xterm 都是**终端模拟器**——一个软件窗口，假装自己是一台 1970 年代的硬件终端。

但底层逻辑没变：
- 输入：键盘 → TTY 驱动 → Shell
- 输出：Shell → TTY 驱动 → 终端窗口

打开哪个终端模拟器都一样——`Ctrl+C` 会杀程序，`Ctrl+Z` 会挂起。这些行为写在操作系统的 TTY 层里，跟窗口软件无关。

我们今天研究终端时看到的 `tty` 这个名字、`/dev/tty` 这个设备文件、`stty` 这个命令——都是 1869 年那条电报线一路传到现在的痕迹。


## 小结

终端的控制字符不是玄学，是几十年前的硬件设计决定的：

- **Ctrl 键 = 清掉高两位**（AND `0x1F`），把字母变成 ASCII 控制字符
- **ASCII 控制字符**来自电报和电传机时代的需求
- **Unix** 把其中一些重新定义为进程控制信号（SIGINT、SIGTSTP）
- **`stty`** 可以查看和修改这些映射
- **今天的终端模拟器**仍然在模仿 50 年前的物理设备

下次按 Ctrl+C 的时候，我们就知道它为什么能杀掉程序了——它是一个从 1962 年穿越过来的 ETX 控制字符，只是被 Unix 赋予了新的使命。
