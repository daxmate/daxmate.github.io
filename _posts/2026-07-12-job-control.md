开了终端在跑一个任务，突然想敲别的命令怎么办？关又舍不得关，开新窗口又麻烦。

Shell 提供了前后台任务管理，不用开第二个终端也能解决问题。

---

## 前台 vs 后台

敲一个命令，它在终端里运行——这叫**前台**。前台任务霸占着终端，你敲不了别的。

想在背后默默地跑，不挡住你敲其他命令——那叫**后台**。

---

## 启动时直接丢到后台：`&`

命令末尾加一个 `&`，就会在后台启动：

```zsh
sleep 30 &
```

```
[1] 12345
```

中括号里的 `[1]` 是**任务编号**，`12345` 是**进程 ID**。

后台任务跑的时候，终端立刻还给你，可以继续敲命令。

---

## 两个容易搞混的操作

初学者经常混淆 `&` 和 `Ctrl+Z`，觉得都是「把任务丢到后台」——但两者的效果完全不一样。

- `&` — 命令**立即在后台运行**，进程状态是 **running**
- `Ctrl+Z` — 命令**暂停**，进程状态变成 **suspended**（被冻住了，什么都不做）

```zsh
sleep 30 &          # 后台跑，running
[1] 12345

sleep 30            # 前台跑
^Z                   # 暂停！变成 suspended
[1]  + 12345 suspended  sleep 30
```

suspended 不是「后台运行」——它是被冻住了，没在做任何事。要让它在后台恢复跑，还得 `bg`。

换个角度理解：**`Ctrl+Z` + `bg` 合起来做的事情，等价于 `&`**。区别只在于时机——`&` 从一开始就后台跑，`Ctrl+Z` + `bg` 是跑了一半再切换。这样一想，两个操作的关系就很清楚了。

---

## 把前台任务放到后台：`Ctrl+Z` 和 `bg`

正在前台跑的任务，也能临时挂起再丢到后台。

```zsh
sleep 300
```

按 `Ctrl+Z`：

```
^Z
[1]  + 12345 suspended  sleep 300
```

任务被挂起了（暂停了），终端还给你。

要让它在后台继续跑：

```zsh
bg
```

```
[1]  + 12345 continued  sleep 300
```

`bg` 把最近挂起的任务放到后台继续跑。

本质上，`命令 &` 做的事情就是：启动进程 + 放到后台。而 `Ctrl+Z` + `bg` 是手动拆分了两步。

---

## 查看后台任务：`jobs`

```zsh
jobs
```

```
[1]  - running    sleep 300
[2]  + running    sleep 100
```

`+` 表示"最近操作过的任务"（默认任务），`-` 表示"上一个默认任务"。

---

## 拉回前台：`fg`

```zsh
fg
```

最近的后台任务拉到前台。

指定某个任务：

```zsh
fg %2       # 把任务 2 拉到前台
fg %sleep   # 按命令名指定
```

---

## 终端关了怎么办：`nohup`

后台任务有一个致命问题：**关掉终端，后台任务也会被杀死**。

为什么？Shell 退出前会给它的子进程发 SIGHUP 信号——告诉它们「我要走了，你们也走吧」。`&` 只是让进程在当前 Shell 会话里后台运行，但它仍然是 Shell 的子进程，躲不过这一刀。

```zsh
nohup 长命令 &
```

`nohup`（no hang up）让进程主动忽略 SIGHUP 信号——终端关闭时它根本不理会。

**为什么还要加 `&`？**`nohup` 只管信号，不管前后台。不加 `&`，进程仍然在前台，关掉终端前它仍然霸占着终端。两者各管一摊，所以通常一起用。

更关键的是，`nohup` 会自动处理输出——如果 stdout 指向终端，它会重定向到 `nohup.out`：

```zsh
nohup ./long-running-script.sh &
```

可以用重定向指定输出文件：

```zsh
nohup ./long-running-script.sh > mylog.log &
```

---

### 忘了 `nohup` 怎么办：`disown`

任务已经在跑了，跑了一阵才发现可能要关终端——不需要杀死重来。

用 `disown` 把它从 Shell 的任务表中移除，终端关闭时 SIGHUP 就不会发给它了：

```zsh
sleep 300 &
disown
```

```zsh
disown %1     # 移除任务 1
```

`disown` 不影响任务继续运行，只是告诉 Shell："这个不归我管了"。

## 一个完整场景

```zsh
# 1. 启动一个编译任务（后台）
make &

# 2. 查看状态
jobs

# 3. 拉到前台看看进度
fg

# 4. 按 Ctrl+Z 暂停，再用 bg 放回后台
bg

# 5. 做其他事
echo "编译在后台跑，我继续写代码"

# 6. 关终端也不怕
nohup make > build.log &

# 7. 或者任务已经在跑了，disown 一下
make &
disown
```

## 历史小注

前后台任务管理是 Bill Joy 在 1978 年的 C Shell（`csh`）里首次引入的，后来才被 `bash` 和 `zsh` 吸纳。当年这项功能算是革命性的——在此之前，想同时跑多个任务只能开多个终端。

---

## 小结

| 操作 | 作用 |
|------|------|
| `命令 &` | 在后台启动 |
| `Ctrl+Z` | 挂起前台任务 |
| `bg` | 挂起的任务在后台继续跑 |
| `fg [%编号]` | 拉到前台 |
| `jobs` | 查看后台任务列表 |
| `nohup 命令 &` | 后台运行，关终端也不停 |
| `disown` | 让已有后台任务不受终端关闭影响 |

记住 `&` 和 `nohup` 这两个就够了。`bg`/`fg`/`jobs`/`disown` 偶尔用到，用的时候翻一下就行。
