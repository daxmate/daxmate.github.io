上一篇我们在文件系统里学会了走路——知道自己在哪，会看目录里有什么，也知道怎么到处走。

现在终于要碰文件本身了。

今天的主题四个字：**增删改查**（CRUD）。不是数据库的那个增删改查，是文件的。在命令行里，创建文件、读取文件、编辑文件、删
除文件——这些是每天操作频率最高的基本功。

---

## 先铺个场地

在开始之前，给自己的文件系统整一块干净的地方，随便折腾。

```zsh
mkdir ~/cmd_practice
cd ~/cmd_practice
pwd
```

`mkdir` 是 **Make Directory** 的缩写——就是新建文件夹。先建一个叫 `cmd_practice` 的目录，然后进去。

> 目录名可以不用带空格的英文和数字。不是不能用空格，是隔空格很麻烦（得加转义或者引号），先从简单开始。

后面的所有操作都在这个目录里进行。玩坏了也不影响别的文件。

---

## 创建文件：`touch`

在命令行里新建一个空白文件，最直接的方式是 `touch`：

```zsh
touch hello.txt
ls -l
```

```
-rw-r--r-- 1 dax staff 0 Jun 28 10:00 hello.txt
```

一个叫 `hello.txt` 的空文件出现了，大小是 0 字节。

`touch` 这个名字挺形象的——"碰一下"这个文件。如果文件不存在，就创建一个空的；如果文件已经存在，就更新它的修改时间戳。

顺便说一句，`touch` 可以一次创建多个文件：

```zsh
touch file1.txt file2.txt file3.txt
ls
```

```
file1.txt	file2.txt	file3.txt	hello.txt
```

批量创建，一秒搞定。这个在新建项目目录结构的时候特别方便。

---

## 往文件里写点什么：重定向

空文件有了，下一步是往里面装内容。

最简单粗暴的方式是**重定向**（后面会专门用一篇讲这个，这里先学会用就行）。

把一句话"喂"进文件：

```zsh
echo "Hello, command line!" > hello.txt
```

这个时候 `hello.txt` 里就有内容了。`>` 的意思是：把左边命令的输出，**写到**右边的文件里。

注意，`>` 是覆盖。如果文件里有内容，会被全部冲掉。如果想**追加**内容到文件末尾，用 `>>`：

```zsh
echo "This is a second line." >> hello.txt
```

`hello.txt` 现在有两行了。

---

## 看文件内容：`cat`

文件里有内容了，怎么看？`cat` 是最简单的办法。它是 **Concatenate** 的缩写，但从它的本意上说——就是把文件内容原样输出到屏
幕上。

```zsh
cat hello.txt
```

```
Hello, command line!
This is a second line.
```

完事儿。`cat` 适合看短文件。长文件它会一口气从头滚到尾，根本来不及看——这种情况我们待会说。

`cat` 还能把多个文件串起来看：

```zsh
cat file1.txt file2.txt
```

（如果文件是空的，当然什么都不显示了。）

---

## 分页查看：`less`

文件长了怎么办？比如一个几百行的日志文件。用 `cat` 看，刷一下就到底了，只看到最后一屏。

这时候用 `less`：

```zsh
less /etc/passwd
```

`less` 会把文件内容分成一屏一屏显示：

- **空格**或 **`f`** 翻下一页
- **`b`** 翻上一页
- **`j`** 下滚一行，**`k`** 上滚一行
- **`/`关键词** 搜索（按 `n` 跳转到下一处匹配）
- **`q`** 退出

这些快捷键不用背，用几次就记住了。核心就四个：翻下、翻上、搜索、退出。

> `less` 当年是为了解决 `more` 的不足而写的。「少即是多」这个梗也是 Unix 世界里一个著名的段子。

---

## 复制文件：`cp`

`cp` 是 **Copy** 的缩写。用法很简单：

```zsh
cp 来源 目标
```

比如：

```zsh
cp hello.txt hello_copy.txt
ls -l
```

`hello_copy.txt` 被创建出来了，内容和 `hello.txt` 一模一样。

复制到别的目录也可以：

```zsh
cp hello.txt ~/Desktop/
```

就把 `hello.txt` 复制到桌面了。目标路径可以是绝对路径也可以是相对路径。

复制整个目录需要加上 `-r`（recursive，递归）：

```zsh
cp -r cmd_practice cmd_practice_backup
```

不亚于把整个文件夹夹起来从头到脚复制了一份。不加 `-r`，目录复制会报错——因为目录底下还有文件，需要递归处理。

---

## 移动和重命名：`mv`

`mv` 是 **Move** 的缩写——移动文件。

```zsh
mv hello.txt sub/
```

把 `hello.txt` 移到了 `sub/` 目录下。

但 `mv` 还有一个同样重要的功能：**重命名**。

```zsh
mv old_name.txt new_name.txt
```

同一目录下，"移动"操作的结果就是改名。当你把文件从一个位置移到同一个位置，就是改了名字。

这个用法很值得习惯。图形界面里改名要右键→重命名，命令行里就是一条命令的事：

```zsh
mv hello.txt greeting.txt
```

完了。`hello.txt` 变成了 `greeting.txt`。

---

## 删除文件：`rm`

`rm` 是 **Remove** 的缩写。

```zsh
rm greeting.txt
```

文件没了。就这么简单，**也没有回收站**。

这是命令行文件操作里**最危险**的命令，没有之一。一旦删了就真的没了。没有弹窗确认，没有撤销按钮，**没有回收站**。

所以这一节除了讲 `rm` 怎么用，更重要的是——**劝你别用**。

---

### 用 `trash` 代替 `rm`

macOS 自带了一个叫 `trash` 的命令，会把文件扔到废纸篓，而不是直接删除：

```zsh
trash unwanted.txt
```

去废纸篓里翻一翻还能捞回来。有没有回收站是天上地下的区别。

**对于初学者，强烈建议只用 `trash`，别碰 `rm`。** 等用熟了、对文件系统有概念了，再自己决定要不要用 `rm`。

如果你实在想用也没人拦得住，但至少养成两个习惯：

1. **删除前列一下确认**

   ```zsh
   ls *.txt  # 先检查有哪些 txt 文件要删
   rm *.txt  # 确认没问题再删
   ```

2. **删除目录加 `-r`，加之前多想想**

   ```zsh
   rm -r something
   ```

有些教程会教你用 `rm -rf`——`-f` 是强制删除（force），不询问直接删。这个组合的威力极大，一个空格打错，`rm -rf ~ /foo` 就
把 home 目录都扬了。初学阶段不要碰 `-f`。

---

### 极端的保护：把 `rm` 禁掉

如果你真的担心手滑，可以直接把 `rm` 命令替换成一个警告，让你每次不小心敲了 `rm` 的时候，看到的不是文件消失，而是一句提醒：

```zsh
alias rm='echo "rm 命令太危险，请改用 trash"'
```

把这行加到 `~/.zshrc` 里，然后 `source ~/.zshrc`，之后再敲 `rm` 就会看到这句提示。想用真正的 `rm` 就敲 `/bin/rm` 或
`command rm`。


---

### 真实案例：一个空格引发的惨案

这不是段子，是真事。

有人想删一个目录，本意是：

```zsh
rm -rf /usr/local/foo
```

结果手抖多敲了一个空格：

```zsh
rm -rf /usr/local /foo
```

看到那个空格了吗？`/usr/local` 后面多了一个空格，变成了两个路径——`/usr/local` 和 `/foo`。`-rf` 递归强制删除，整个
`/usr/local` 目录瞬间被扬了。

系统工具链全在 `/usr/local` 下面——git、node、python、各种库……全没了。

这种错误在 Stack Overflow 上隔一段时间就有人问：「我不小心 `rm -rf` 了系统目录，怎么办？」下面回答永远是：**没办法。没有
回收站。从备份恢复吧。**

如果你没有备份（大多数人都没有），那就只能重装系统了。

这就是为什么前面说——**宁可极端一点，别碰 `rm`**。

## 一次看多个文件：通配符

刚才说到 `ls *.txt`，那个 `*` 星号是 Shell 里最基本的通配符，代表「任意多个字符」。

`*.txt` 就是「所有以 `.txt` 结尾的文件」。

通配符在很多命令里都能用，不只是 `ls`：

```zsh
cat *.txt         # 看所有 txt 文件的内容（串起来）
cp *.txt backup/  # 把所有 txt 文件复制到 backup 目录
rm *.tmp          # 删除所有 .tmp 文件（谨慎！）
```

除了 `*`，还有一个常用的通配符 `?`，代表**一个**任意字符：

```zsh
ls file?.txt
```

会匹配 `file1.txt`、`fileA.txt`，但不会匹配 `file10.txt`（因为 `?` 只占一个位置）。

## 动手试试

新建一个目录，然后从头到尾折腾一遍：

```zsh
mkdir ~/cmd_practice
cd ~/cmd_practice

# 创建几个文件
touch readme.txt notes.txt data.csv

# 往里写内容
echo "This is my readme file" > readme.txt
echo "Notes for today" > notes.txt

# 看看内容
cat readme.txt

# 复制一份
cp readme.txt readme_backup.txt

# 改个名
mv notes.txt diary.txt

# 建个子目录并把文件移进去
mkdir archive
mv readme_backup.txt archive/

# 看看结构
ls -la
ls -la archive/

# 通配符列一下再删（用 trash 别用 rm）
ls *.txt
trash diary.txt

# 清理整个练习目录（可选）
trash ~/cmd_practice
```

按顺序跑一遍，感受一下创建→查看→复制→改名→移动→删除的完整流程。

## 小结

这一篇我们把文件的增删改查过了一遍：

| 命令 | 作用 | 常用搭档 |
|------|------|----------|
| `touch` | 创建空文件 | 可一次创建多个，空格分隔 |
| `>` / `>>` | 写入 / 追加内容 | 与 `echo` 配合 |
| `cat` | 查看短文件内容 | 多个文件一起看 |
| `less` | 分页查看长文件 | 空格翻页、`/`搜索、`q`退出 |
| `cp` | 复制文件 | `-r` 复制目录 |
| `mv` | 移动 / 重命名 | 同一目录下就是改名 |
| `trash`（推荐） | 移到废纸篓 | macOS 自带，比 `rm` 安全一百倍 |
| `rm` | 直接删除 | **没有回收站，极度危险。初学者建议用 `trash` 代替** |
| `mkdir` | 新建目录 | 记得先 `cd` 进去 |

还学会了通配符 `*` 和 `?`，让批处理操作脱胎换骨。

下一篇我们深入文件内容的查看和搜索——`cat` 只是开胃菜，`grep`、`head`、`tail` 才是真正好用的东西。
