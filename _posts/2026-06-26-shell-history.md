上一篇我们把终端和 Shell 分清楚了：终端是窗户，Shell 是窗户里跟我们说话的那个人。

但有一个问题当时没细讲——**Shell 为什么有这么多版本**？sh、bash、zsh、fish……它们都是什么关系？为什么要换？现在 Linux 和 macOS 上又各用什么？

这篇就是来回答这些问题的。不涉及实操，但搞懂了这些来龙去脉，后面学命令的时候心里会更有底。

---

## 一切的起点：sh（Bourne Shell）

电脑很长时间里是没有 Shell 的。最早的计算机连键盘都没有，程序要插拔线缆来写。后来有了打孔纸带、再后来有了磁带——但这都算不上交互。

真正的转折点发生在 Unix 上。

Unix 诞生于上世纪 70 年代初的贝尔实验室。一开始 Unix 也没有 Shell——系统启动后直接加载一个程序，干完活就结束。

但 Ken Thompson 觉得这样不够方便，于是他写了第一个真正意义上的 Shell，叫 **sh**。这就是老祖宗。

## sh 的进化：Bourne Shell

后来 Unix 越来越流行，sh 也越来越强大。1977 年，Stephen Bourne 为 Unix V7 重写了 sh——支持了变量、流程控制、输入输出重定向。我们今天能看到的大部分 Shell 语法，都能追溯到 Bourne Shell。

所以 **sh**（Bourne Shell）是所有后续 Shell 的基础。直到现在，几乎所有 Unix 系统上都还保留着 `/bin/sh`。

## bash：GNU 时代的爆发

80 年代，自由软件运动兴起。Richard Stallman 的 GNU 项目想要一个完全自由的 Unix 兼容系统。自由的系统需要自由的 shell。

于是 1989 年，Brian Fox 写出了 **Bash**——Bourne Again SHell。名字是个双关：它既是 sh 的增强版，又"再次诞生"了（born again）。

Bash 比 sh 多出了很多功能：命令补全、历史记录、数组、算术运算……而且它是**完全自由的**。

Linux 选择了 Bash 作为默认 Shell。随着 Linux 在服务器、嵌入式设备、云计算等各个领域的爆发式普及，Bash 成了世界上使用最广泛的 Shell。

可以这么说：**如果只学一种 Shell，Bash 是最稳妥的选择。** 几乎在任何 Unix 类系统上都能找到它。

## zsh：站在 bash 的肩膀上

1990 年，普林斯顿大学的 Paul Falstad 开始写 Zsh。名字里的「Z」来自当时一位教学助理 **邵中**（Zhong Shao，姓 Shao 名 Zhong）的登录账号 `zsh`。邵中是普林斯顿的助教，后来成了耶鲁大学教授——他自己并没有参与 zsh 的开发，但名字就这么被借用了。

有趣的是，美式英语里「Z」读作 /ziː/，和「C shell」（csh）的发音押韵（sea-shell），也算是个无心插柳的谐音梗。

zsh 兼容 bash 的大部分语法，但在很多细节上做得更好：

- **更强的 Tab 补全**：Bash 的补全比较基础，zsh 可以做到极致的智能——敲 `cd ` 再按 Tab，它只显示目录；敲 `kill ` 再按 Tab，它会列出进程名
- **拼写纠正**：敲错目录名，zsh 会问"你是想说 xxx 吗？"
- **丰富的主题**：类似 `oh-my-zsh` 这样的框架让提示符可以变得非常漂亮
- **更友好的默认配置**：很多在 Bash 里需要手动配置的功能，zsh 默认就是好用的

2019 年，macOS Catalina 把默认 Shell 从 Bash 换成了 zsh。从此 zsh 成了 Mac 用户的默认选择。

我们现在打开终端用的就是 zsh，这也是整个系列默认的 Shell。

## fish：为交互而生

在 Bash 和 zsh 之外，还有一个设计理念很不同的 Shell——**fish**（Friendly Interactive Shell）。

fish 和传统 Shell 最大的区别是：**它没有历史兼容包袱。**

Bash 和 zsh 都在努力兼容 40 年前的 sh 语法，这意味着很多糟粕也要保留。fish 不在乎这些——语法重新设计，开箱即用：语法高亮、自动补全建议、Web 配置界面。

但 fish 也有代价：它的脚本语法和 Bash/zsh 不兼容。这意味着我们从网上找到的绝大多数 Shell 脚本都不能在 fish 下直接运行。

所以 fish 适合作为交互式 Shell 用，但不适合作为脚本编写环境。

## 现在：百花齐放

回到开头的问题——现在用哪个？

| Shell | 位置 | 说明 |
|-------|------|------|
| sh | 所有 Unix 系统 | 底线标准，写脚本时最通用的选择 |
| bash | Linux 默认、macOS 可选 | 最广泛，服务器/脚本首选 |
| zsh | macOS 默认、Linux 可选 | 交互体验最好，Mac 用户直接上手 |
| fish | 需要单独安装 | 交互式很爽，脚本不兼容 |

**用 Mac 的同学**：系统默认就是 zsh，不需要换，专心用就行。

**用 Linux 的同学**：大概率默认也是 Bash，但如果换成 zsh 也不亏。

**无论用哪个**：这个系列 99% 的命令在任何 Shell 下都通用。如果有细微差别，我会特别提醒。

## 多说一句：关于历史兼容

最后想说一个可能被忽略的事实——我们现在用的 Shell，语法来自 50 年前。

我们在终端里敲的 `if`、`for`、`while`，和 1977 年的 Bourne Shell 几乎一样。这个语法不是计算机语言里最好用的，但它通行五十年，说明它在实践中经住了考验。

那些看起来奇怪的设计——比如变量赋值 `=` 两边不能有空格、`[ ]` 前后必须有空格、`$?` 表示上一条命令的退出码——不是设计者在为难人，而是 1970 年代留下的历史印记。

了解了这些之后，再看那些古怪的细节，是不是就没那么烦人了？
