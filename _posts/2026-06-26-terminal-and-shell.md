上篇我们打开了终端，看到了一个闪烁的光标，敲了 `echo "Hello, world!"` 和 `ls -la`。

但有个细节值得注意：上一篇里我用了两个词——「终端」和「Shell」。它们经常被混着用，但其实不是一回事。这篇就来把它们拆开讲
清楚。

---

## 终端和 Shell，到底谁是谁

打个比方就容易懂了：

**终端**（Terminal）是窗户，**Shell** 是窗户里面跟我们说话的那个人。

打开 Terminal.app，看到的是一个窗口。这个窗口负责显示文字、接收键盘输入。但它自己什么命令都不懂——它只是把说的话传进去，
把回答显示出来。

真正听懂命令、帮我们干活的那个，是 Shell。

在 macOS 上，打开终端后默认跑的是 **Zsh**（Z Shell）。Linux 上可能是 **Bash**。它们都是一类东西：命令行解释器。

所以当别人说「打开终端敲命令」的时候，实际发生的事是：终端窗口启动了一个 Shell，把键盘输入喂给 Shell，Shell 执行命令，终
端把结果打印出来。

---

## 为什么叫「终端」

这个名字是有历史原因的。

最早期的计算机非常昂贵，一台主机要同时给几十甚至上百个人用。每个人面前放的不是一台独立电脑，而是一个「终端机」——一个只有
屏幕和键盘的设备，通过线缆连接到远处的主机。

终端机自己不运算，它只做两件事：把键盘输入传给主机，把主机的输出显示到屏幕上。

那时的终端长这样：

- **电传打字机**（Teletype，简称 TTY）：长得像打字机，敲字会同时打印在纸上。输入命令，计算机算完结果，咔咔咔打印出来

![tty](/assets/images/teletype.jpeg)

- **视频终端**（Video Terminal）：后来有了屏幕，比如大名鼎鼎的 VT100。终于不用废纸了

![Video Terminal](/assets/images/DEC_VT100_terminal.jpg)

今天我们用的 Terminal.app、iTerm2、Windows Terminal，学名叫「终端模拟器」（Terminal Emulator）——用软件模拟当年那些物理终
端机的功能。敲 `tty` 命令，还能看到古老的命名遗迹：

```zsh tty # 输出类似: /dev/ttys001 ```

TTY 就是 Teletype 的缩写。一个上世纪七十年代的名字，用到了现在。

---

## 为什么叫 Shell

Shell 翻译过来就是「外壳」。为什么这么叫？因为它**包裹着操作系统内核**。

计算机的最底层是硬件，操作系统直接跟硬件打交道的那一层叫**内核**（Kernel）。内核是核心，但普通用户不能直接跟内核说话——太危险了，一封邮件就能把系统搞崩。

所以在内核外面包一层程序，用户跟它说话，它把需求转给内核，再把内核的回应翻译成人能读懂的格式。这层壳就是 Shell。

```
用户 → Shell（外壳）→ Kernel（内核）→ 硬件
用户 ← Shell（外壳）← Kernel（内核）← 硬件
```

这样用户既能用电脑，又不至于误操作把内核炸了。

理解了这层关系之后，「Shell」这个名字就不再神秘了——它就是操作系统内核外面那层壳，做的是翻译和调度的工作。

---

## Shell 不止一种

Shell 是真正干活的那个。打开终端，连上的那个就是 Shell。

最常见的几种：

| Shell | 全名 | 特点 |
|-------|------|------|
| sh | Bourne Shell | 老祖宗，几乎所有 Unix 系统自带的底线 |
| bash | Bourne Again Shell | sh 的加强版，很长一段时间是 Linux 默认 Shell |
| zsh | Z Shell | bash 的超集，功能更强，macOS 现在 的默认 Shell |
| fish | Friendly Interactive Shell | 开箱即用，不需要配置就很好用 |

我们不用把每种都学一遍。如果用 Mac，系统默认就是 **zsh**，已经很够用了。这个系列后面的文章也都是基于 zsh 来写的。

怎么确认自己用的是哪个？

```zsh echo $SHELL # 输出: /bin/zsh ```

## 提示符在跟你说什么

上一篇我们看到了那个闪烁的光标。光标左边还有一串字，大概长这样：

``` dax@macbook ~ % ```

这不是乱码。把它拆开：

- `dax` — 当前用户名
- `@macbook` — 这台电脑的名字
- `~` — 当前所在的目录（`~` 是 home 目录的简写，相当于 `/Users/用户名`）
- `%` — 提示符，表示 Shell 准备好了，等我们输入命令

所以这一串东西翻译成人话就是：「用户 dax，在 macbook 这台机器上，目前在 home 目录，请下命令吧。」

Bash 的提示符结尾是 `$`，zsh 是 `%`。看到哪个符号，就知道自己大概在哪个 Shell 里。

---

## Shell 怎么工作的：一个极其简单的模型

Shell 的工作方式可以用四个字概括：**读-解-做-回**。

1. **读**：等我们敲完回车，读入输入的一整行
2. **解**：把这一行拆开——哪个是命令、哪个是参数、哪个是选项
3. **做**：找到对应的程序，让操作系统去执行
4. **回**：把结果打印到终端上，然后打印一个新的提示符等我们

不断循环，直到关掉窗口。这就是所谓的 **REPL**（Read-Eval-Print Loop）。

举个例子。我们输入：

```zsh ls -la ~/Downloads ```

Shell 把它拆成三部分：`ls`（命令）、`-la`（选项）、`~/Downloads`（参数）。然后找到 `ls` 这个程序，告诉它：「嘿，列出
Downloads 文件夹的详细内容，包括隐藏文件。」`ls` 干活，Shell 把结果打印出来。

下一个提示符出现了。循环继续。

## 小结

这一篇我们搞清楚了两个容易被混用的概念：

- **终端**是窗口程序，负责显示和输入
- **Shell** 是命令解释器，负责理解和执行指令

它们的关系就像浏览器和网页——我们用浏览器打开网页，看到的内容是网页提供的。换一个 Shell，就像打开了一个功能更丰富的网页。

现在搞清楚了谁是窗户、谁是窗户里跟我们说话的那个人。但 Shell 这个「人」本身还有很多故事——它从哪来？sh、bash、zsh、fish 都是什么关系？

下一篇我们停下实操，聊聊 Shell 的发展史。搞清楚了这些来龙去脉，后面学命令的时候心里会更有底。
