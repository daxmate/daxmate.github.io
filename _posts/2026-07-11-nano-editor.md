到现在我们学会了查看文件、操作文件、用管道处理文本。但还缺一个基本技能——在终端里编辑文件。

SSH 到远程服务器要改配置，在 Docker 容器里要写脚本，纯终端环境没有桌面——这些场景都需要一个能跑在终端里的编辑器。经典的两个选项——Vim 和 Emacs——都很好，但新手第一次打开 Vim 连打字都做不到，更别说退出了。

于是有了 **nano**。

---

## 为什么是 nano

选择 nano，有几个实在的原因：

**一、几乎无处不在。** macOS 自带，Ubuntu 预装，最小化的 Docker 镜像也带着。不用装。

**二、没有模式。** 打开就能打字，不存在"忘记按 i 进入插入模式"这种事。键盘就是拿来打字的。

**三、底部两行是速查表。** 最重要的操作直接显示在屏幕上，不用翻文档、不用背快捷键。

**四、轻量够用。** 改个 Nginx 配置、编辑 crontab、写个临时脚本——这些 nano 做来绰绰有余。

等用上瘾了觉得不够，再升级到 Vim 也不迟。

---

## 打开和退出

```zsh
nano hello.txt
```

界面很干净：上面是文件名，主区域编辑，底部两行快捷键提示。

编辑完了，退出三步：

1. **`^X`**（Ctrl + X）
2. 问要不要保存，**Y**（yes）
3. **Enter** 确认文件名

如果想不保存直接退出——同样按 `^X`，提示保存时按 **N**，再按 N 确认，就退了。

---

## 底部那两行就是帮助

nano 最有特色的设计：最下面始终显示常用操作的快捷键。

这些符号的意思：
- **`^`** = Ctrl 键，`^X` 就是 Ctrl+X
- **`M-`** = Alt 键（Mac 上是 Option），`M-A` 就是 Alt+A

按 **`^G`** 能打开完整的帮助文档——所有快捷键都在里面。

---

## 日常操作

### 保存、搜索、替换

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 保存 | `^O` | 保存但不退出，像 GUI 编辑器的 Ctrl+S |
| 退出 | `^X` | 退出，会提示是否保存 |
| 搜索 | `^W` | 输入关键词，跳到匹配位置 |
| 继续搜索 | `M-W` | 跳到下一个匹配 |
| 替换 | `^\` | 搜索并替换，逐个确认是否替换 |
| 显示帮助 | `^G` | 完整的快捷键文档 |

`^O` 是写文章时用得最多的——写几行按一次，相当于保存存档。

### 剪切、粘贴、选中

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 剪切行 | `^K` | 剪切光标所在行 |
| 粘贴 | `^U` | 把剪切的内容粘回来 |
| 标记选中 | `M-A` | 开始选中文本，方向键移动光标扩大选中的范围 |
| 选中后剪切 | `^K` | 选中一块文字后按 `^K`，剪切选中的内容 |

连续按 `^K` 可以快速剪切多行（每次剪一行），然后一次 `^U` 全部粘贴回来。删除大块内容时特别方便。

### 其他

- **撤销：** `M-U`，重做：`M-E`
- **跳转行号：** `M-G`，输入行号
- **显示位置：** `^C`，看光标在第几行第几列
- **读取文件：** `^R`，把另一个文件的内容插入到当前光标位置

## 调一调 `~/.nanorc`

想让 nano 更好用，可以在 `~/.nanorc` 里加点配置：

```ini
set linenumbers         # 显示行号
set autoindent          # 自动缩进
set tabsize 4           # 制表符宽度 4
include ".../nano/*.nanorc"  # 语法高亮
```

语法高亮那行要指向 nano 语法文件的实际位置。macOS 系统自带的 nano 没有语法文件，可以安装 Homebrew 版获得（`brew install nano`），语法文件在 `/opt/homebrew/share/nano/` 下。Linux 通常在 `/usr/share/nano/`。

```zsh
# 先确认一下路径
ls /opt/homebrew/share/nano/*.nanorc 2>/dev/null || ls /usr/share/nano/*.nanorc 2>/dev/null
```

加上行号和语法高亮，nano 的编辑体验会好很多。

## 什么时候用它

nano 不是万能工具，但在特定场景下非常合适：

**用它：** 改配置文件、编辑 crontab、远程服务器上快速修东西、Docker 容器里写脚本。

**升级：** 经常在终端里大量编辑代码时可以考虑学 Vim；主力开发用 VS Code 或 Cursor。

但有一点值得说：**只会 nano 不丢人。** 能在终端里把文件改好，比"我在终端里打开 Vim 但退不出来"强多了。工具看场景，不是看难度。

---

## 小结

nano 能做的其实就是这三件事——打开文件、编辑内容、保存退出。它不复杂，也不需要复杂。

下次在终端里要改文件时，试试 `nano 文件名`，看看底部的提示就好。第一次用可能还要确认一下是 `^X` 退出还是 `^O` 保存——瞄一眼底部就有答案。
